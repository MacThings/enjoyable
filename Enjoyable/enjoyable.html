New in 1.3.1

  • Added: Launch Enabled option. Enjoyable can now start with mapped actions enabled automatically, so there is no need to toggle it manually after every launch.
  • Added: Clone Mapping. The active mapping can now be duplicated directly from the Mappings menu or the mapping popover. Clones include all assignments and receive an automatically unique name.
  • Improved: Mapping selector and popover. The Mappings toolbar button now keeps a stable width, the popover uses a consistent width and adapts its height to the number of mappings, and unnecessary empty rows were removed.
  • Improved: Mapping controls. Add, remove, clone, move up and move down controls were reorganized and made easier to use. Moving the first mapping down now works correctly, and mapping reordering is kept in sync with the underlying data.
  • Improved: Enabled state indicator. The toolbar now shows a green status lamp with “Enabled” and a red status lamp with “Disabled” instead of the previous arrow/stop-style symbols. Toolbar labels reserve enough space so their text is not clipped when the state changes.
  • Fixed: Joy-Con and modern macOS controller handling. Synthetic Game Controller HID devices created by macOS are filtered out when Enjoyable uses the direct HID path, preventing duplicate controller sources that could cause repeated detection or flashing.
  • Fixed: Analog controller axis handling. HID axis values are now normalized using their logical range, improving neutral/dead-zone behavior and reducing unwanted axis activity, especially with Nintendo Joy-Cons and similar controllers.
  • Fixed: Toolbar compatibility on recent macOS versions. Deprecated toolbar item sizing was removed and toolbar items now use system measurement, preventing sizing warnings and potential clipping.
  • Fixed: AppKit layout recursion during startup. Toolbar creation and layout were reworked to avoid recursive layout warnings and improve startup stability on newer macOS versions.
  • Fixed: Window restoration warning on startup. Enjoyable no longer attempts to restore an unsupported window state.
  • Fixed: Multi-display mouse handling. Mouse movement and mouse-button output are more robust when displays are added, removed or temporarily unavailable.
  • Fixed: Mapping import and activation edge cases. Invalid mapping files are handled more safely, and imported/merged mappings now activate the correct existing mapping.
  • Improved: General controller and runtime stability. HID device setup, display-link initialization and several controller/input edge cases were hardened for current macOS versions.
